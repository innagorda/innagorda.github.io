## Архитектурные концепции

**ACID** — набор требований к транзакциям в реляционных БД:
- **Атомарность**: выполнение всех операций транзакции или ни одной
- **Консистентность**: переход БД из одного согласованного состояния в другое
- **Изоляция**: отсутствие влияния параллельных транзакций друг на друга
- **Долговечность**: сохранение результатов после фиксации транзакции

**BASE** — противоположный подход для NoSQL-систем:
- **Базовая доступность**: система должна быть всегда доступна
- **Согласованность в конечном счете**: допускаются временные несоответствия данных
- **Мягкое состояние**: данные могут изменяться со временем

**CAP-теорема** — фундаментальное ограничение распределенных систем: одновременно могут быть полностью реализованы только два из трех свойств:
- **Консистентность**: все узлы видят одинаковые данные в один момент времени
- **Доступность**: система всегда отвечает на запросы
- **Устойчивость к разделению**: система продолжает работать при разрыве связи между узлами

## Современные архитектуры данных

**Data Mesh** — децентрализованная организационная архитектура, где данные принадлежат бизнес-доменам, а не центральной IT-команде. Основные принципы: доменно-ориентированное владение, данные как продукт, инфраструктура как платформа.

**Data Fabric** — единая технологическая архитектура, автоматически соединяющая разрозненные источники данных через метаданные. Обеспечивает самообслуживание, автоматизацию и безопасный доступ.

## Архитектуры обработки данных

**Лямбда-архитектура** — комбинированный подход для обработки больших данных:
- **Скоростной слой (Stream)**: обработка в реальном времени, быстрый, но приблизительный результат
- **Батч-слой (Batch)**: пакетная обработка, медленный, но точный результат

**Каппа-архитектура** — упрощенная альтернатива, где весь поток обрабатывается через стриминг, а пакетная обработка рассматривается как частный случай стриминга.

## Основы моделирования в реляционных БД

**Нормализация данных** — процесс организации структуры базы данных для устранения избыточности и аномалий. Нормальные формы (НФ) обеспечивают целостность данных:
- **1 НФ**: атомарные значения, отсутствие повторяющихся групп;
- **2 НФ**: отсутствие неключевых атрибутов, зависящих от части составного ключа;
- **3 НФ**: отсутствие транзитивных зависимостей между неключевыми атрибутами;
- **НФБК**: дополнительное требование — отсутствие перекрывающихся ключей, что часто приводит к выделению справочников в отдельные таблицы.

**Slowly Changing Dimensions (SCD)** — методы обработки изменений в исторических данных:
- **SCD1**: перезапись данных без сохранения истории;
- **SCD2**: создание новой записи с новым ключом и указанием периода действия;
- **SCD3**: добавление новых столбцов с дублированием предыдущих версий атрибутов.

## Масштабирование БД 

**Вертикальное (Scale Up)** — добавление ресурсов к одному серверу. Дороже из-за нелинейного роста стоимости мощного оборудования, физических ограничений архитектуры сервера и создания единой точки отказа.

**Горизонтальное (Scale Out)** — добавление новых стандартных серверов в кластер. Дешевле за счет линейной стоимости типовых компонентов, возможности использовать отказоустойчивость через программное обеспечение и гибкого наращивания мощности.

**Терминология**:
- **Секционирование/партиционирование** — <u>логическое разделение</u> таблицы на части по определенному правилу для управляемости и оптимизации.
- **Распределение/сегментация/шардинг** — <u>физическое разделение </u>данных между узлами кластера для масштабирования и отказоустойчивости

- **Репликация** — создание полных копий данных на разных узлах. Не является разделением, а скорее дублированием для доступности и чтения.
- **Кластеризация** — объединение серверов в единую логическую систему, где данные могут быть как разделены (шардинг), так и реплицированы.

## Партиционирование данных

**Горизонтальное партиционирование** — разделение таблицы по строкам:
- **По диапазонам значений**: для последовательных данных (даты, ID)
- **По хешу ключа**: для равномерного распределения
- **По таблице соответствий**: через директории
- **По географии**: расположение сервера близко к пользователям

**Вертикальное партиционирование** — разделение колонок по разным таблицам, например, по частоте использования/изменения.

## Распределение данных в кластерах

**Типы распределения данных** между узлами:

- **Хэш-распределение** — данные распределяются по узлам на основе хэша ключа. Обеспечивает равномерную нагрузку и эффективные точечные запросы.
- **Распределение по диапазонам** — данные группируются на узлах по логическим диапазонам значений (дат, идентификаторов). Оптимально для запросов с предикатами диапазонов.
- **Реплицированное распределение** — полные копии таблиц хранятся на каждом узле. Эффективно для небольших справочников, устраняет сетевой обмен при JOIN.
- **Распределение по списку значений** — явное сопоставление значений конкретным узлам (например, по регионам или типам клиентов).
- **Циклическое/случайное распределение** — данные распределяются по узлам по кругу или случайным образом для простой балансировки без учета семантики данных.
    

**Motion-операции (перемещение данных между узлами)**:

- **Перераспределение (Redistribute/Shuffle)** — Пересылка строк между узлами для группировки связанных данных (например, по ключу соединения) перед операциями JOIN, GROUP BY, ORDER BY.
- **Широковещательная рассылка (Broadcast)** — Копирование всех данных одной (обычно маленькой) таблицы на все узлы кластера. Используется, когда перераспределение большой таблицы неэффективно.
- **Сбор (Gather/Merge)** — Передача результатов выполнения запроса со всех узлов на один координирующий узел для формирования окончательного ответа.
- **Локализация (Local)**: операции выполняются на том же узле, где находятся данные, без перемещения.

## Методы сканирования таблиц

**Полное сканирование таблицы (Full/Sequential Scan)**:

- Последовательное чтение всех строк таблицы с диска.
    
- Используется, когда запрос затрагивает большую часть строк таблицы, или когда таблица небольшая, или отсутствует подходящий индекс.
    

**Сканирование по индексу (Index Scan)**:

- Доступ к данным осуществляется через структуру индекса. Сначала читается индекс, затем по найденным указателям извлекаются соответствующие строки из таблицы.
    
- Используется для точечных запросов и запросов по диапазону, когда индекс может существенно сократить количество читаемых данных.
    

**Только индексное сканирование (Index-Only Scan)**:

- Частный случай Index Scan, когда все необходимые для запроса данные содержатся в самом индексе, что исключает обращение к таблице.
    
- Максимально эффективный метод при покрывающих индексах.
    

**Сканирование по битовой карте (Bitmap Scan)**:

- Гибридный метод: сначала через индекс формируется битовая карта подходящих строк, затем происходит эффективное чтение только этих строк из таблицы в оптимальном порядке (минимизируя случайные чтения).
    
- Используется при сложных условиях с несколькими предикатами, которые можно комбинировать через битовые операции (AND, OR).
